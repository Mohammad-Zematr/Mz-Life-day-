# MZ Life OS

نظام شخصي عربي باتجاه RTL لإدارة اليوم والمهام والمواعيد والملاحظات والدراسة والاستوديو والمال والعادات والأهداف. تصميم داكن بالأحمر والأسود، يعمل على الهاتف والكمبيوتر، ويمكن تثبيته كتطبيق ويب.

## التشغيل محليًا

1. ثبّت Node.js **24.15.0 أو أحدث**.
2. افتح PowerShell داخل مجلد المشروع.
3. شغّل:

   ```powershell
   npm start
   ```

4. افتح `http://127.0.0.1:4173` وأنشئ الحساب الأول.

لا توجد حزم npm خارجية. يستخدم الخادم SQLite المدمجة في Node.js، ويحفظ قاعدة البيانات داخل `data/`.

## الوظائف المنفذة

- حساب بكلمة مرور قوية، رمز استعادة يُعرض مرة واحدة، وتسجيل خروج وحذف حساب.
- عزل سجلات الحسابات، جلسات HttpOnly، تقييد محاولات الدخول، والتحقق من مصدر طلبات الكتابة.
- لوحة يومية، مهام ومواعيد وتقويم شهري، ملاحظات وبحث، جلسة تركيز، متابعة دراسة ومشروعات الاستوديو.
- دخل ومصروفات بالجنيه المصري، عادات وسجل يومي، وأهداف شخصية وصحية.
- حفظ تلقائي في SQLite، ومزامنة عند الاتصال، مع كشف تعارض التعديلات بين الأجهزة.
- نسخة محلية مشفرة بـ AES-GCM ومفتاح مشتق من كلمة المرور، ونسخ JSON للتصدير والاستيراد.
- نقل بيانات الإصدار الأول من المتصفح بعد عرض خيار التصدير أو الدمج.
- تصميم متجاوب ووضع داكن وقابلية تثبيت PWA بعد أول زيارة عبر الخادم أو HTTPS.

## الخصوصية وحدود الإصدار

- الخادم افتراضيًا يستمع إلى `127.0.0.1` فقط. لا تعرضه على الإنترنت مباشرة.
- كلمات المرور مخزنة ببصمة scrypt، لكن قاعدة SQLite نفسها غير مشفرة على القرص. استخدم جهازًا موثوقًا، وفعّل HTTPS عند الاستضافة، واحمِ النسخ الاحتياطية.
- النسخة المشفرة في المتصفح لا تحل محل نسخة احتياطية مستقلة. تنزيل JSON من الإعدادات هو تصدير لسجلات التطبيق، وليس نسخة كاملة من الحسابات وقاعدة البيانات.
- التسجيل مفتوح لإنشاء الحساب الأول فقط. لا يوجد تحقق بريد إلكتروني أو إرسال تلقائي لرسائل الاستعادة. يمكن للمشغل فتح التسجيلات اللاحقة عبر `ALLOW_REGISTRATION=1`.
- الدراسة والعمل والصحة والعادات تُسجّل يدويًا. لا توجد مزامنة تقويم خارجي أو ربط مصرفي أو مرفقات ملفات.
- مواقيت الصلاة والقرآن والطقس والإشعارات الخلفية وTelegram والبريد ومساعد الذكاء الاصطناعي غير موصولة بخدمات خارجية في هذا الإصدار؛ لا تظهر بيانات تجريبية على أنها حقيقية.
- لا تستخدم هذا التطبيق لمعلومات صحية أو مالية حساسة قبل إعداد استضافة ومراجعة أمنية ونسخ احتياطية مناسبة.

## الاستضافة بواسطة Docker

يتطلب النشر عنوان HTTPS عامًا وتخزينًا دائمًا للمجلد `/data`. ضع التطبيق خلف وكيل HTTPS، وحدد الأصل العام الدقيق. مثال متغيرات الحاوية:

```text
HOST=0.0.0.0
PORT=4173
MZ_DATA_DIR=/data
PUBLIC_ORIGIN=https://your-domain.example
COOKIE_SECURE=1
ALLOW_REGISTRATION=0
```

ابنِ الصورة وشغّلها مع مساحة تخزين دائمة:

```sh
docker build -t mz-life-os .
docker run -d --name mz-life-os --restart unless-stopped \
  -p 127.0.0.1:4173:4173 -v mz-life-os-data:/data \
  -e PUBLIC_ORIGIN=https://your-domain.example mz-life-os
```

وجّه وكيل HTTPS إلى `http://127.0.0.1:4173`. أنشئ الحساب الأول بعد التشغيل، ثم اترك التسجيل مغلقًا. احتفظ بنسخ احتياطية مشفرة من مساحة `mz-life-os-data`.

## الرفع إلى GitHub

ارفع محتويات مجلد المشروع `mz-life-os` إلى مستودع جديد. يستثني `.gitignore` قاعدة البيانات وملفات البيئة والسجلات. GitHub Pages لا يشغّل `server.js` أو SQLite؛ استخدم استضافة Node.js أو Docker للحسابات والمزامنة.

- `index.html` و`style.css`: واجهة RTL والتصميم.

- `test/server.test.js`: اختبارات الخادم.
